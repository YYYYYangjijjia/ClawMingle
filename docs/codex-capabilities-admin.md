# Codex 能力目录与可选迁移

管理后台的「任务与扩展 → Codex 能力与迁移」统一展示本机可迁移能力与已登记连接。
ClawMingle 在接入 Codex App Server 时自动准备通用工作环境；命令、文件、Skills、
搜索和浏览器遵循相应工具开关及会话范围。管理员无需为每种普通任务开发一个插件。

打开页面只读取本机 Codex 的 MCP 配置、用户 Skills、可选命令 Hooks 和已缓存的账号应用，不停止机器人。
显式点击「刷新账号应用目录」后，通过 `clawmingle capability-catalog --config <配置>`
获取机器人独立 Codex 登录可用的账号应用。检查先等待机器人空闲，短暂停止它以释放
operator lock，再执行目录探测，并在成功或失败后恢复原先的运行状态。忙碌时明确返回提示，
不打断正在处理的消息。
该过程不发送 QQ 消息，不运行模型任务，不执行 MCP 命令或自定义鉴权脚本，也不读取或
复制个人 `auth.json`。页面只展示名称、类型、可用状态及工具名，不返回凭据、源路径或端点。
账号应用目录不可用时，页面保留本机能力管理，并给出明确状态。未连接、未提供只读工具
或无法确定工具归属的应用仍出现在目录中，说明原因并禁止导入或重新启用。

选择工具后点击「导入所选能力」。新导入的 MCP、账号应用、Skill 和 Hooks **默认停用**。
连接可在同一目录启用、停用或检查；启用后还须在「群聊管理」或「私聊管理」为对应会话
选择授权。导入和全局启用不会替任何会话添加权限。停用连接保留现有授权，以便再次启用。
账号应用只接受目录返回的精确工具名，通过机器人独立 Codex 登录执行。
工具名沿用 Codex 原始 MCP 名称，支持裸名及带点的名称；不按应用显示名猜测前缀。
每次调用仍核对原生目录中的应用标识、工具名称和只读属性。

本机 MCP 自动迁移支持公开 HTTPS 端点及普通 Bearer 鉴权。Bearer 可以来自配置中的
`Authorization` 或管理服务已有的 `bearer_token_env_var`；只有管理员选择导入时才将
所需凭据保存到机器人的私有文件。普通 HTTPS 配置没有工具清单时，须填写已核对的工具名。
「检查连接」验证登记工具是否存在，不执行实际内容查询。

需要 stdio 子进程、自定义请求头或鉴权程序的 MCP 会显示当前不可迁移原因；TikHub 等
已有专用连接继续使用原有设置。此目录不会以执行本机配置命令的方式猜测连接能力。
仅含 `SKILL.md` 的本机 Skill 可直接导入，之后在「人格与能力 → Skills」中启用。
包含脚本或资源的技能包继续使用固定版本的技能包安装流程，避免只复制说明却遗漏依赖。
已有同名 Skill 不会被覆盖。

本机 `~/.codex/hooks.json` 作为一个可选「命令 Hooks」项目展示，默认不导入、不执行。
只接受当前用户所有、权限为 `0600`、无符号链接或硬链接的普通文件；读取和格式检查
不会执行命令或匹配表达式。页面不返回命令、配置描述、源路径或状态提示中的私有内容。
支持原生事件分组中的 `type: "command"`，最多 32 条、总文件最多 64 KiB。
命令最长 8192 字符，`timeout` 如提供须为 1–600 的整数；保留 `async`、`statusMessage`
和 `additionalContextLimit`。不接受 Windows 命令、`env`、其他 Hook 类型、未知字段、
源文件中的权限状态或重复 JSON 键。不支持的项目保留在目录中并说明原因。

导入原样保存到机器人独立的 `runtime/codex/hooks.disabled.json`，并用
`hooks.import.json` 记录本模块的导入标识和内容摘要。点击「启用 Hooks」才切换成
`hooks.json`；停用时切回备份，保留原内容。启用后作用于后续原生任务的相应事件，
不同于账号应用的逐会话授权；命令仍受原生工作环境约束。导入只复制 Hooks 配置，
不复制命令依赖的脚本、个人登录、个人环境变量或其他个人配置；管理员需先核对依赖
在机器人工作环境中可用。源文件随后删除不影响已导入项的启停。

三个目标名称中只要存在非本模块管理的文件、内容摘要不符、活动文件与备份同时存在，
或链接、权限异常，就拒绝操作，不覆盖手工配置。启停和导入均在现有空闲检查、
operator lock 与配置检查事务内进行；检查失败会恢复每个文件原有字节及存在状态。

所有保存操作沿用后台的空闲检查、operator lock、配置校验和失败回滚。能力目录选择
十分钟后过期；导入时重新核对本机配置与 Skill 内容，源文件变化后需要刷新再选择。

后台统一使用已有的 `POST /api/config`，传入 `section: "capabilities"`。`action: "catalog"`
读取本机与缓存目录；`refresh` 启动账号目录后台任务并立即返回状态，`status` 轮询任务。
单个 CLI 最长等待 100 秒，轮询请求不等待 CLI，也不受代理 60 秒上游超时影响。刷新期间其他
修改明确返回 busy，不与停服、校验和恢复步骤并行。重复刷新会返回正在运行的同一任务。

`import`、`enable`、`disable`、`check` 接收目录给出的 `id`；MCP、账号应用导入时另传
`allowed_tools`。Hooks 只接受 `import`、`enable`、`disable`，无需选择工具，也不接受
命令或文件路径参数；保存时只校验配置，不提供执行命令的「检查连接」动作。
直接访问管理服务仍兼容 `GET /api/capabilities` 只读目录及 `POST /api/capability` 操作；
这两个路由不是部署界面对外层代理的要求。请求不能指定执行命令、源路径、端点、应用标识
或凭据路径；认证和 CSRF 继续由既有后台代理保护。目录和表单内容都作为数据渲染。

后台从私有的 `data_dir/runtime/native-tools.json` 读取原生浏览器准备状态，仅接受
`version: 1`、`browser_ready: true` 及受保护的文件权限。显式关闭浏览器配置优先于该状态。
安装后台时须将 `scripts/codex_capabilities.py` 与 `clawmingle_admin.py` 放在同一目录。
