# 部署 ClawMingle

推荐由编程 Agent 按[部署手册](agent-deployment.md)在目标机器上完成环境检查、构建、安装和验证。你主要负责账号准备和网页中的首次设置；不必逐项复制安装命令。

## 你需要准备什么

- 一台可登录的 Linux 机器。当前安装流程使用 systemd 用户服务，管理台只监听本机；远程机器通过 SSH 隧道打开页面。
- [QQ 开放平台](https://q.qq.com/)创建的官方机器人、AppID 和 AppSecret，以及一个允许测试该机器人的群。平台要求的测试成员、群权限或来源地址白名单需在平台配置。
- 机器人自己的 Codex 登录，或兼容 Responses 协议的模型服务凭据。使用自己的独立机器人运行目录，不复制个人 Codex 的历史或配置。
- 如需 `mode-2`／`mode-3` 的语义参与判断，准备 Jev 的 API Key。首次仅 @ 回复的 `mode-1` 可以先不填。

QQ、模型和 Jev 的可用性与费用由各自服务决定。将密钥填写在管理页，不要发送到群聊、Agent 对话或 Git。

## 把部署交给 Agent

将 [README 的部署请求示例](../README.md#部署让-agent-完成环境准备)交给能够操作目标机器的 Agent。它应该：

1. 检查系统、工具和已有安装，确认能使用非特权 Bubblewrap，保留已有配置与数据。
2. 构建应用和辅助程序，安装管理台与群登记依赖，准备用户服务。
3. 启动本机管理台，给出访问方式。首次配对信息只用于你自己的浏览器，不应写入公开报告。
4. 等你完成网页设置和模型登录，再启动机器人并验证。

管理台不要求另装网站或 personal-dashboard。已有 personal-dashboard 的部署可以继续使用代理接入；它是该环境的可选整合方式。

## 在网页完成首次设置

1. **打开管理页并设置管理员密码。** 本机访问 `http://127.0.0.1:17430/`；远程机器由 Agent 给出 SSH 隧道访问方法。你在自己的终端查看 `~/.config/clawmingle/admin-bootstrap.json`，将其中的配对码填入页面并设置密码；不要把文件内容发给 Agent。该密码保护管理台，与 QQ、Codex 账号密码不同。
2. **填写机器人配置。** 输入 QQ AppID／AppSecret、可选 Jev Key，并选择模型与推理强度。页面会提示未满足的本机条件。
3. **登记测试群。** 点击登记，在目标 QQ 群真正 @ 机器人并发送页面显示的一次性口令。登记只识别本次口令，成功后绑定群；这一步不会生成模型回复。已有平台 OpenID 时也可手动填写，普通 QQ 群号不能代替 OpenID。
4. **完成初始化。** 页面保存私有配置并进入管理台，不安装或启动机器人服务。首次默认 `mode-1`、关闭私聊；后续在管理台按需修改。
5. **完成机器人独立登录。** 在账号配置中发起 Codex 设备登录，按官方页面操作；或配置模型服务。确认登录和本地配置状态后再启动机器人。

通过一次性口令登记时，实际发送口令的成员会登记为首位群命令管理员。不要让无关成员代发。手动填写 OpenID 时同时核对群和管理员标识；昵称、QQ 群号和平台成员 OpenID 不是同一类标识。

首版是一位管理者的本机管理台，没有多人管理账号或公网托管功能。浏览器初始化只用于新安装；已有配置直接登录管理台编辑，不会被初始化覆盖。

## 第一次试用

在测试群 @ 机器人，发一条简短问题，确认能收到回复。通过管理台检查服务、群状态和模型登录。不要仅凭“配置检查通过”认定 QQ 权限、模型额度或真实收发已经验证。

如需日常群聊参与，在填好 Jev 凭据后选择 `mode-3`；帮助优先可选 `mode-2`。机器人只能判断平台实际送达的消息，若 QQ 账号仅有 @ 事件权限，切换模式不会产生全量群消息权限。

Identity 和 Soul 是共享身份与人格；本群的用途、角色、风格与边界放在本群档案。各群工具授权和私聊开放单独设置，见[管理台说明](admin.md)。

## 数据和可选能力

配置与认证默认放在 `~/.config/clawmingle/`，聊天、记忆、任务文件和模型运行资料放在 `~/.local/share/clawmingle/`。所有已收到的聊天，包括没有回复的消息，都可能在私有存档中保留。上下文压缩、重置和减少窗口条数不等于删除这些数据。

每日记忆整理与表情功能的设置在管理台显示，部署后按需求检查。备份默认未启用，需要自行启用并选择保留策略。浏览器、群文档和其他扩展需要相应依赖、账号授权及会话权限；可以先完成基础聊天再配置它们。

浏览器首次准备需要访问 Node/npm/Chromium 下载源、具备 Linux 浏览器系统库，并满足磁盘预留规则：下载前留出较大的 `15 GiB` 或文件系统 `20%`，另加 `1 GiB` 安装余量。无法满足时应先关闭浏览器，或让 Agent 解决缺失的依赖；不要为了启动聊天而移除隔离与权限保护。详见[运行环境](native-runtime.md)。

## 常见问题

| 现象 | 检查方向 |
| --- | --- |
| 管理页打不开 | 确认管理服务在运行、SSH 隧道未断开，并打开隧道本地地址；无需开放公网端口。 |
| 首次配对码过期 | 配对码有效期为 30 分钟；重启管理服务后由你查看新的配对文件。 |
| 初始化提示已有数据 | 让 Agent 核对现有安装与路径；不要删除数据或重复初始化。 |
| 群登记一直等待 | 确认机器人已加入测试群，真正 @ 它，发送当前页面口令；重新登记会得到新口令。 |
| 配置通过但机器人启动失败 | 检查独立 Codex 登录、原生程序与 Bubblewrap；浏览器启用时也检查下载和系统库。 |
| 仅 @ 有反应 | 先核对参与模式；`mode-2`／`mode-3` 还需要 Jev 和 QQ 的相应收消息权限。 |
| 模型返回 429 | 查看模型服务可用性和额度；应用会控制请求和退避，但无法保证上游永不限流。 |
| 更新后行为没变化 | 让 Agent 比较运行程序与安装版本，确认是否实际重启了对应服务；Git 更新不等于部署。 |

升级、备份及回退应由 Agent 按[部署手册](agent-deployment.md#更新与回退)执行，保留认证和聊天数据。不要把整个运行目录或日志提交到 Git。
