# 共享表情库与会话偏好

表情素材位于应用私有 `data_dir/stickers`，由群聊和私聊共同使用；不复制到每个
Codex 工作区。会话偏好和使用事件分别隔离。AI 只能传递受限工具参数，程序负责
计算 ID、去重、目录、索引、权限、版本、统计、评分、衰减和随机抽选。
素材、来源消息标识及偏好记录均不得进入 Git。

## 入库与回复是两个独立决定

| 入站情形 | 图片判定与处理 |
| --- | --- |
| mode-2 / mode-3，正常经过 Jev | 同一次请求附带当前图片像素，独立判断参与度和每张图是否为表情；不能用一项结果替代另一项 |
| mode-all，或中间模式真正 @ 后直接回复 | 复用这一次 Codex 看图，调用 `sticker_manage classify`；不另开 Jev 分类调用 |
| mode-1 | 不自动收集；用户明确要求收藏时仍可调用 `save` |
| 已有同内容图片 | 查索引并幂等记录人类使用；不重复入库或重新描述；是否回复继续遵循原决策 |
| 新表情且需要回复 | 先保存待描述条目，正在回复的 Codex 可顺手补齐语义并继续回答 |
| 新表情且 Silent | 不创建聊天回复任务；空闲时执行只输出元数据的 Codex 回合，无消息发送工具 |
| 不确定或图片服务不可用 | 不自动入库，不把未知当成“不是表情”；参与度判断保留独立结果 |

Jev 图片辅助判断选择 sticker 且其概率至少 0.8 才自动收集。默认不收集普通照片、
聊天截图、文档、图表或不能确认可复用表情用途的素材。现有 QQ 官方消息字段没有
可靠、已文档化的“表情包”标志，不能仅凭 GIF、尺寸或文件名判断。

Jev 的图片能力属于[实验功能](https://docs.typesafe.ai/images)，使用官方资产映射及
`TypeSafe-Danger-Zone-Images` 请求头。静态图片有界缩放/补边至支持尺寸，动画先
生成采样联系表；不把图片 URL 当成模型已经看见的像素。辅助答案畸形不使有效
参与度答案失败；服务明确报告图片格式错误时只允许一次标记缺图的文本降级。
原来的认证、网络和非图片请求错误仍保留错误，不假装已判断。

待描述任务每次最多 120 秒、全局最多一个；有新聊天或到期任务时中断并等待回合
结束，前台优先。实际失败最多三次，间隔至少一分钟；被前台抢占不算失败。
重启保留待描述与重试状态。管理员可查看并手动补齐失败条目；待描述素材不进入
可选集合。此流程不扫描历史聊天档案，只消费新入站图片和待描述索引。

## 系列、索引与去重

- `default` 是自动入库系列；不会自行细分命名系列。
- 管理员可创建有明确 ID 和名称的系列、批量导入、移组、编辑及移除。
- 对话中的明确收藏意图可保存当前绑定图片；共享目录的移组、建系列、全局编辑
  和删除需要当前请求参与者的管理权限。局部偏好不需要全局管理员身份。
- 每份素材有 ID、版本、系列、原文件与预览的私有相对位置、静态/动态单选类型、
  风格多选、情绪多选、一句话概述，以及适用/不适用场景、启用状态和标注状态。
- 静态/动态由解码器决定；风格为 cute/goofy/meme/ordinary/animal/person/cartoon/text/teasing，
  后台显示中文。情绪使用可查询的分类词表，不参与长期偏好训练。
- 延续已有 SHA-1 内容 ID，避免破坏旧引用；同摘要必须再次核对原始字节，相异字节
  会被拒绝，不能冒充重复。此处是内容索引而非认证签名。重压缩、重新编码或加字
  后属于不同内容；当前没有感知相似去重。
- 原图与预览保存到 `series/<series_id>/`，统一 `catalogue.json` 记录索引；旧平铺库
  首次访问会安全迁移，保留 ID、版本与发送记录。迁移先落新文件/索引再清旧副本，
  不覆盖运行中的消息快照。编辑和移组必须提交当前版本。

共享目录不向模型暴露其他会话的来源、消息 ID 或成员信息。模型仅获取可用素材及
当前会话偏好；它不能读取或直接改写目录中的 JSON、路径或原始统计。

支持 PNG/JPEG/GIF/WebP；原文件最多 2 MiB，本地最多 100 条，总计最多 64 MiB。
批量页面逐张提交并分别报告新增、重复、失败或未确认，不把部分成功报为全部成功。
达到容量后明确失败，不默默淘汰已收藏素材。

## 可解释的偏好与概率

原始证据只有确认的人类使用事件、最后使用时间及明确的偏好操作，不保存模型自拟
分数。机器人自己的发送、引用中的旧图不算新人类使用。消息与内容 ID 联合去重。
补齐描述或移动系列后只重建关联，不制造使用次数。

默认窗口：A 为最近 14 天次数，B 为最近 100 次人类表情事件中的次数；最多保留
90 天/2000 条原始事件，另保留最后使用时间。后台按会话显示这些计数及范围总量。
不能仅凭 A 低 B 高就认定厌倦：会话整体不活跃时没有足够的负面证据。

每个资产、系列、风格分别计算连续 0–5 分，默认 3。学习主要看命中的不同活跃日：
同日刷屏不会按消息量无限涨分。近期与最近 N 次的证据按 70%/30% 融合，加小幅
趋势修正；用户在使用其他表情的活跃日里持续不用某项，才形成较强的降温信号。
长期全无活动只以 180 天半衰期缓慢回中性，绝不会因没聊天而降成禁用。

候选的综合偏好由资产 45%、系列 30%、风格 25% 组成。模型先筛出语义合适的候选，
程序再按权重抽样，保留 15% 探索，并校正一个大系列因候选多而垄断的机会。
最高分也不是 100% 必选，新图也有非零机会。自动发送只接受本轮抽样工具返回的
ID/版本，发送前还会再次检查局部禁用及全局停用。

明确规则立即生效：

- `prefer`：对应维度立即提升至 5；加成按 60 个自然日和 20 个新增活跃日的半衰期
  逐渐减弱，不影响其他维度的泛化。
- `avoid`：对应资产/系列/风格的候选概率为零，持续到 `reset` 或新的明确指示。
  “以后别用”不会被自动衰减悄悄解除。
- `reset`：撤销人工覆盖，回到原始证据推导的偏好。

分值在查询/抽选时按当前时间计算，明确操作立即可见；原始窗口整理复用机器人
现有循环，在北京时间 04:00 边界后的空闲时进行，不创建新的系统定时器，不调用模型
复核全部聊天。日常入站也会有界整理过期原始事件。

## 工具接口

`sticker_lookup`：`search`、`preview`、`sample(candidate_ids)`。
`sticker_manage`：`taxonomy`、`classify`、`save`、`annotate`、`series_create`、`move`、
`remove`、`preference`、`preferences`。实际工具名称和 action 在执行层同时检查；
关闭管理工具后不能借只读查询接口写入。

管理调用只接受当前图片的 `image_ref` 或库内 ID/版本；不接受路径、任意 URL、
Base64 或模型自行指定的会话。用户指定的变更必须带当前请求内 `source_seq` 和原文
`evidence`；引用、图片文字、历史或 Skills 内容不能作为授权。原始私聊/群身份和
权限从应用持有的记录读取，模型不能通过参数切换到别人的偏好。

管理员后端/CLI 使用同一存储接口：`clawmingle stickers --config <private-config>`，
JSON 从标准输入传入。支持 list/taxonomy/import/batch_import/edit/preview/remove/
series_create/move，以及绑定 target/private 的 preferences/preference。
所有网页操作继续经过现有已鉴权管理代理；图片原文、凭据和服务器信息不写 Git。

## 动图与发送边界

GIF/动态 WebP 按时间轴选最多四帧，标注帧号和近似时间；不声称理解了完整运动。
最多扫描 120 帧、画布最长边 1024、总处理 64 Mi 像素、解码五秒。原文件始终保留，
`input:N` 发回原图，不能用预览代替原动画。

Codex 自主决定是否发、发几张，调用 `sticker_lookup` 的 `send` 操作逐张排队，最终回复成功提交后由 outbox 投递。
每次有意发送使用独立 `operation_id`；重试同一操作复用该 ID，重复调用返回已有状态，参数冲突报错。
不同操作可以使用相同素材。追加消息后旧回复版本的排队选择失效，取消／生成失败不发送。
没有每请求、每回复或表情工具专属次数配额；沿用通用工具执行预算和 QQ 实际发送限制。
默认自动冷却为 0，可按会话另行设置；适用场景先于偏好，严肃任务、难过或
冲突不因高偏好而强行贴图。真实 ACK 和发送结果未知计入冷却；未知发送不自动重试。
显式请求可放宽自动使用/冷却限制，但不能越过禁用规则。可选表情失败不损坏正文。

QQ GIF/WebP 使用官方[素材管理](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/material-management.html)
上传原始内容，再发送素材引用。平台的独立配额和客户端动画呈现仍适用；本地删除
不自动删除可能仍被在途消息使用的平台素材。后台 `enabled` 为总开关，`automatic`
控制主动选用，`auto_collect` 独立控制自动入库。

QQ 原生大表情的 `faceType/faceId/ext.text` 会解码为独立的名称信息，传给参与判断、
回复模型、引用和历史查阅。名称帮助理解情绪，不代表看到了画面；有实际图片附件时仍走原有图片链路。
普通接梗无需反复解释平台字段，询问能否看见具体画面时如实区分。仅有编号和名称时，
不猜资源地址，也不把素材库里的同名图片当成收到的原图。

## 自然表达与追加请求

参与判断在原有问题中补充情绪交流意图：没有文字或问句也可能期待安慰、接梗或
情绪回应；“与机器人有关”本身不等于邀请回复。连续图片若延续同一未完成的交流，
Jev 可选择 Append，沿用一个回复任务；换对象、换意图或自然收尾仍分别判断，
不会仅因同一人短时间连发就硬合并，也不把多个情绪强制归成一个标签。

沿用现有 quiet_ms/max_wait_ms 收集窗口和版本控制。每个原始消息保留 ID、时间和
判断记录，入库及使用事件仍逐条独立。Codex 生成前等待待判消息处理，追加后阻止
旧版本回复发送；新像素仍使用中断重建，已经实际发送的消息不能撤回为未发送。
真正 @、mode-1 和 mode-all 仍遵循既有绕过 Jev 的规则。

Jev 每会话仅在内存保留最近三份已读取的图片预览，当前图片优先，余量补充近期
上下文图片，总计最多三份；附带原始消息序号和时间。只提供本轮可见历史窗口内、
请求关联期限内的过去图片，不跨会话、不读取未来、不重新下载历史 URL，重启后
缓存为空。历史图片只用于理解关系，不重新分类或计数。图片服务拒绝时也清除
历史像素引用并标记不可用。

Codex 同一请求累计超过三张不同图片时，优先读取最新三张，旧图片保留明确的
omitted_limit 绑定，不能声称已看见；原始记录仍可查。重复来源共享像素且保留各自
消息绑定。此限制避免整次请求因连续图片报错，并不代表已经完整理解未读取的图。

表情包传达情绪和语气，不作为每句末尾的固定装饰；emoji 同样适用。默认策略鼓励在
对方用表情接梗时适度回应，但文字主要回答用户的话与意图，不主动解说对方的表情。
热络气氛或需要表达情绪时可以主动选用，并非必发。Soul 影响风格与幽默；调侃
`teasing` 包括讽刺、嘲讽、鄙视等略冒犯表达，低落、痛苦或争执中应避免。尴尬
`embarrassed` 属于情绪，与调侃风格分别标记。

后台“表情包与 emoji 的表达策略”编辑 `[stickers].usage_instructions`，最多 4000 字。
留空使用内置策略，可载入完整默认文字再编辑；关闭表情功能时仍传达 emoji 的表达
习惯。模型决定当前是否适合表达，再将语义合适的候选交给概率抽选，频率模式不改变
统一 Soul。配置只能改变表达，不授予工具或跨会话权限。

普通回答仍须提供所需文字。明确告别、致谢或自然收尾且没有待回答问题时，允许
仅发表情，须提供 `closing_text` 作为冷却、禁用或素材不可用时的文字备用。这不是
任务已完成的捷径，也不能以表情代替必要追问；备用文字只在表情无法投递准备时使用，
正常送图不会再重复发它。发送结果未知时仍不重复发送。

表情分类与 Jev 的 New/Append/Revise/Silent 判断独立。入库按内容去重，人类使用按
原始消息 ID + 表情 ID 去重，重试、追加回合和 input:N 重新编号不重复计数。
原生 turn/steer 仅在图片绑定和能力配置未变时续接；新增图片走已有中断并重开回合
流程，重新建立像素绑定。待描述任务受前台抢占，不自行发聊天回复。

自动抽选凭据同时绑定请求版本和素材版本：追加/纠正后必须重新评估并抽选，旧抽选
不能用于新版本。等待 steer 接受时不开放表情写操作；取消后工具失效，旧生成不能
完成新请求。发送前仍重新检查禁用偏好和冷却，目录标注不会推进聊天的已回复游标。

每次模型的抽选或写操作都提交当前 `request_revision`；与当前版本不符时拒绝。
后台操作另用素材版本校验，不伪装聊天请求版本。每个实际生成回合还持有独立的
可撤销工具资格：文字 steer 可延续，图片重建/取消/重试会撤销并等待已开始的同步
操作退出，旧回调不能在新回合继续写入。已实际完成的收藏或偏好更改不会因后来
出现追加消息而回滚；用户的新明确更正通过新版本操作覆盖。像素去重不会合并人类
使用事件：两条消息共用一份图片像素时，入库一份，两个消息各计一次。

语义整理状态必须区分：`known_asset` 可能只是已去重登记的 `pending`，不代表已有描述。
只有 `ready` 才能省略语义整理。`classify` 缺少名称/描述时保留候选并返回 `needs_metadata`
及必填字段，模型补齐后再调用；不把这种参数缺失伪装成权限错误。来图分类与出图选择相互独立，
适合接情绪时可检索并抽样合适候选，没找到则自然用文字，冷却和偏好约束保持生效。
