# 长任务进展、澄清与结果投递

ClawMingle 把“已经接到并开始处理”“仍在处理”“需要补充信息”和“最终结果送达”分开记录。普通闲聊和快速问答直接回答，不增加任务回执；复杂任务由 Codex 根据实际需求选择长任务预算，不额外调用 Jev 分类。Jev 继续负责参与和请求关联，Soul 在各模式保持一致。

## 用户体验

- 预计需要多轮检索、工具、代码操作或等待时，Codex 先调用 `task_update(kind=ack)` 给出一句自然的开始说明。应用持久化后排队发送，与模型继续工作并行。
- 有实际新发现或阻塞变化时可以调用 `task_update(kind=progress)`。标准档进展之间至少 45 秒；只发送有实质内容的进展。反馈档位独立于参与模式。
- 回执由 Codex 判断长任务后自行撰写，说明当前任务要做什么；程序只负责排队、去重和投递，不按等待秒数生成模板回执。普通闲聊、身份问题和已完成任务的轻量续接直接回答。发送前再次检查修订与完成状态，已过时的回执取消。
- 只有已明确选择长任务的请求，标准档才会在 90 秒没有更新时，根据真实执行事件补充状态；没有新执行证据时明确“无法确认是否仍在推进”，同一段沉默只提醒一次。确认／进展发送失败或结果未知后停止自动补发，保留查询能力。
- `/status` 列出最近任务，`/status R编号` 查看详情和投递原因。点击按钮仅填入命令，手动发送后查询。明确、独立的“弄好了没”“你还在查吗”等短句也可直接查询；群聊必须能确定在问机器人，mode-1 仍要求真实 @。这些查询不会等待长任务，也不会重跑任务。
- 长任务的应用动态工具结果附带只读计时提示：总耗时、距最近实际送达的模型进展秒数、是否已有进展待发送；到提醒点时提示 Codex 自行说明已完成内容、当前步骤或真实卡点。原生 web search／exec 结果不经过该桥，模型仍需按提示主动检查时间。提示不自动发消息、不改变任务预算或权限。
- 进展不代表完成，不推进正式答案的生成／完整送达游标。工具返回 `queued` 也不等于 QQ 确认送达。
- 关键条件缺失时，最终结构中的 `outcome=needs_input` 提交最少的澄清问题。问题送达后请求保持 `waiting_for_user`，当前模型 turn 结束，不占着工具等人回复。
- 私聊中，若只有一个同发起人、近期已送达的问题，下一条普通消息关联为同请求的新修订。新的明确意图可以修订或放弃先前要求，不强行继续旧话题。多个等待请求或超出关联时间窗时，引用对应问题或发送 `/continue R编号 答复`。
- 群聊中间模式的自然续答仍交 Jev 判断；极端模式保留原来的参与规则，但引用已送达澄清问题且具有请求身份的答复可以准确关联。
- 其他新请求仍进入该会话的队列；本版没有“后台子代理运行、主模型同时自由聊天”的承诺。控制命令和 Jev 关联的补充仍在执行期间处理，符合条件的补充使用原生 `turn/steer`。

## 配置

后台及私有配置的 `[interactions]`：

| 字段 | 默认 | 范围／用途 |
| --- | --- | --- |
| `enabled` | `true` | 开始说明、进展和复杂任务档位 |
| `feedback_mode` | `standard` | quiet 仅确认与按需查询；standard 标准反馈；detailed 更密的有用进展 |
| `ack_delay_seconds` | `5` | 旧配置兼容字段，已停用并在后台隐藏；不再触发自动回执 |
| `heartbeat_interval_seconds` | `90` | 0 关闭，或 30–1800 秒；执行状态提示间隔 |
| `long_timeout_seconds` | `0` | 0 为长任务不限总时长；可选 60–3600 秒有限预算，有限预算绝对计时不重置，至少保留普通任务预算 |
| `workspace_timeout_seconds` | `120` | 1–300 秒；单次命令上限，默认参数仍为 20 秒，取消／超时后先杀死并回收子进程 |
| `tool_calls` | `48` | 1–128 次每轮应用动态工具调用；历史读取另有 48 次限制，原生 web search 不包含在此计数中 |
| `long_max_bubbles` | `4` | 1–8 个最终内容气泡，包括图片；这是上限，不是要求凑满 |
| `long_bubble_chars` | `2000` | 100–2000 字／文本气泡 |
| `max_progress_messages` | `2` | 每条原消息最多 1–3 条被动进展，包含确认；为最终答案保留额度 |
| `progress_interval_seconds` | `45` | 10–300 秒；重复 ACK 不再排队 |

启用交互时，`tool_calls` 与 `workspace_timeout_seconds` 是每轮应用工具的授权上限，不需要先发送 ACK；只有执行总时限和最终气泡上限由 ACK／进展选择扩展。关闭 `enabled` 后不提供 `task_update`，恢复原每轮 12 次应用工具和单次命令最多 30 秒，也不会继承未完成任务已选择的长任务预算。

长任务默认不限总时长，也不因三分钟没有模型输出而被应用主动结束；后台明确显示 `0` 为不限。单次工具超时、后端断线处理、用户 `/cancel` 仍然生效。普通任务在选择长任务前仍有原来的有限预算；不会将进展当作完成，也不会因超时自动重跑可能已产生外部效果的任务。若管理员主动设置有限总预算，耗尽时记录 `reply_deadline_exceeded`，与其他生成失败分开；已收到的消息与过程记录保留，用户可要求继续。

普通回复仍使用现有 `max_bubbles`／`max_bubble_chars`。单次沙箱命令使用上述授权上限；扩大模型预算不等于无限输出量或并发。全局单命令槽以及网络／文件隔离保持不变。

## QQ 窗口与较长结果

按 [QQ 当前官方规则](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)，群聊每条原消息最多 5 泡／300 秒，私聊最多 4 泡／3600 秒；取消项目原有统一 290 秒的提前截断。进展至少为最终结果预留两个被动额度；额度或窗口不足时，只能使用已授权的同会话主动推送。没有授权则保留状态供查询，工作继续。界面切换到详细档会建议 20 秒进展／60 秒状态间隔；标准档建议 45／90 秒。重新加载不会覆盖自定义间隔；安静档不发送后续自动状态或模型里程碑。

最终结果始终先持久化。适用被动窗口时正常投递；窗口过期或剩余额度不足时：

1. 当前会话允许主动推送（新对话默认开启，管理员可用 `/task push off` 关闭），并且任务功能开启：尝试使用 QQ 主动文本或普通 PNG／JPEG 图片、文件发送。只发回原会话，不改变收件人；真实可达性仍受 QQ 权限、频控和配额限制。
2. 会话关闭推送、平台明确拒绝或附件类型暂不支持主动发送：保留为 `awaiting_delivery`。原请求发起人、参与者或当前会话管理员可发送 `/continue` 或 `/continue R编号`，把尚未送达的结果绑定到这条新消息；不会重新调用模型或重跑代码。超过新 anchor 五泡的部分继续保留，可再次取回。
3. QQ 发送结果未知：保留 `unknown_delivery`，不自动重发，也不重新执行任务。需先使用已有管理核对流程确认。

主动发送使用与被动回复相同的配置格式，保留 Markdown、链接、按钮和 `message_reference` 原生引用；省略用于被动额度的 `msg_id`，两者互不混用。只有来源缺少合法 QQ 引用索引时才使用可读原文摘要，不伪造索引。发送拒绝或未知不会自动重试为纯文本。普通图片和文件支持主动发送，GIF／WebP 素材仍需新消息窗口取回。正常被动最终回复继续使用自动延迟引用；进展曾经引用过消息不阻止最终答案再次标明回复对象。

## 状态与权限

消息原文、来源、ACK、每泡投递状态和请求修订继续归入现有历史库，可被 `message_lookup`／`messages_list` 查询。`task_ack`、`task_progress`、宿主生成的 `task_heartbeat`、`clarification` 明确区别于最终 `model_answer`。`needs_input` 不推进完整回答游标；只有当前修订的实际最终内容全部被确认送达，才能标记完成。

进展工具接受 `kind`、短文本及可选 `quote_seq`（本任务来源消息的会话内序号），线程、请求、会话、收件人及权限由宿主管理。取消后工具租约撤销；请求修订期间的过期进展不接收。原生 steer 的精确 turn、ACK、输入消费与最终答案校验保持不变。中断未确认时不复用该后端继续执行。

后端通知发生丢失时，应用不能假定任务仍在执行或已经完成：撤销工具租约，发出中断并在有限的协议确认窗口内核对准确的线程与 turn ID。只有中断 ACK 不算结束；无法确认时退出该后端，避免无限等待或复用仍在执行的会话。这是故障恢复期限，不是正常长任务总时限。

插件、浏览器、原生多代理与这些进度接口是独立能力：提高预算或发送 ACK 不授予新的文件、联网、登录态或外部写入权限。当前长任务功能不会直接启用原生多代理，也不会自动继承个人 Codex 插件和账号。

## 投递诊断与恢复

生成完成与 QQ 送达分别记录。被动窗口过期且未开启推送、回复额度不足、图片需要新窗口、认证不可用、平台明确拒绝与发送结果未知会保存独立的安全原因、时间和可用的数字错误码；不保存上游响应正文或凭据。历史旧任务若没有原因记录，会明确标为未记录，不让模型猜测。

`/status R编号` 提供剩余条数和取回按钮。每条 `/continue R编号` 仅发送该任务已经保存、且确认尚未送达的内容。未开启主动推送或主动投递不成功时，图片与文件也可用新的消息窗口取回；其他人的无关聊天不能用于给旧任务续期。未知投递必须先核对，不能用取回操作重复发送。

新版本会在同会话推送可用时恢复此前因本地窗口或推送关闭而暂存、且确认未送达的结果，不重跑模型。平台已知拒绝、上传失败、发送未知不会自动反复重试。

## 任务时间编号

任务显示编号采用首次请求的北京时间 `YYYYMMDD-HHMMSS`，例如 `20261025-143205`。同秒冲突或迟到/时钟回退时追加内部唯一序号，例如 `20261025-143205-95`。编号持久化且不随追加、修订、重启、重置对话或状态变化而改变；内部请求 ID 保持不变。`/status`、`/continue`（含澄清答复）、`/cancel` 支持时间编号，同时兼容历史 `R94` 命令和按钮。存量请求使用保留的最初来源时间迁移；来源已不可用时保留 R 编号，不用更新时间伪造创建时间。按钮短标签为“查看任务进度”，完整编号显示在消息中并填入命令。
