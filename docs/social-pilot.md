# ClawMingle 群聊开发版

这个入口提供“QQ 群／私聊消息 → 参与及关联判断 → 请求版本 → Codex → 回复投递”的运行流程。
它与原来的 `codex-claw` 入口分开，复用 QQ 和 App Server 模块，但不自动导入个人会话、
认证、Skills、记忆或调度任务。原来的 `cargo run` 仍默认运行上游入口；群聊试点使用
新二进制 `clawmingle`。

## 当前行为

| 情况 | 路由 |
| --- | --- |
| 真实 @ 机器人 | 保证回应机会；mode-2/3 有可关联的未完成请求时，仍用 Jev 判断新请求或追加／修订／取消；其余情况直接新建 |
| `mode-1` 的其他消息 | 保留上下文，保持静默，不调用 Jev |
| `mode-2` / `mode-3` 的其他消息 | Jev 判断静默、新请求、补充、修订或取消，并选择主要回应对象和样式 |
| `mode-all` | 每条有效消息分别创建回应请求，不调用 Jev |
| 只引用机器人 | 中间模式仍交给 Jev；引用本身不构成 @ |

默认 `mode-1`；模型默认 `gpt-6.1-sol`，推理强度 `high`。
模式、窗口、模型、推理强度、Provider 和气泡限制均可配置。QQ 群全量接收权限是否开放，
仍须针对真实 Bot 验证；只接到 @ 事件时，中间模式也看不到其他聊天。

`mode-2` 偏向帮助需求和显式／隐式对机器人的交流；`mode-3` 也把面向群里的
日常分享、情绪和共同话题视为可参与的机会，不要求先提问或点名。人对人交流是否
适合插话由当前模式及语境判断，明确拒绝、专注的定向交流、自然收尾和近期参与平衡
仍需考虑。Jev 判断记录的 `policy_version = 5` 标记这一版通用问题定义；具体模式
提示词仍以管理员配置为准。这是语义选择，不是固定回复比例或降低概率阈值。
给机器人的进度说明和省略主语的自然续接也可能需要回应；同一次调用中的独立
`exchange` 判断区分对机器人说话、开放话题和面向特定人类的交流。若判定为专注的
人对人交流且没有明确机器人寻址/指代时，程序不新开一次插话；已有任务操作另行判断。

表达由统一 Soul 和后台“回复策略 → 闲聊”控制，与参与模式分开。闲聊优先回应具体
内容、表达看法和顺势接梗，避免用复述、旁白解释笑点或固定追问代替交流；严肃问题
和用户要求的解释继续按需展开。已有配置中的自定义提示词不会被新默认值自动覆盖，
更新时需在后台选择性修改并保存。后续连续短消息仍沿用原有语义追加流程，不逐条强制回答。

短句默认等待 1.2 秒安静窗口，持续输入最多收集 4 秒；这两个值只控制收集时机，
不证明语义归属。收件批内按消息顺序判断，每条需要 Jev 的消息发起一次请求，
在这次请求内按下文独立分支并行判断参与、对象、指代、任务关系和样式。下一条会看到前一条已创建的请求。
这与执行层的短回复合批不同：积压中的独立短回复可经 Jev 重审后共享一次 Codex 输入，
每个请求仍独立保存结果、引用与投递状态。见[合批与积压重审](message-context.md#短回复合批与积压重审)。

mode-1 的真实 @ 与 mode-all 由确定规则创建请求；mode-2/3 的真实 @ 在已有任务时也可语义关联。
私聊还有等待澄清时的续接规则，见[长任务](long-tasks.md)。中间模式允许多人补充，
修订／取消及管理操作仍核验真实发送者与相应权限；时间相邻、引用和昵称不能授予权限。

## 状态和更新

- 按群保存原始消息、引用作者/正文、判断状态、来源、完整选择概率和请求关联。
  QQ scene 中的 `auth_token` 在解码时丢弃。平台给出的语音转写及其状态会保存；图片可按来源
  下载到私有缓存供 Jev/Codex 读取，即使原消息未单独回复，后续任务仍可选入有效的图片。
  当前与近期视觉输入、缓存期限、表情收集分别有界，见[消息上下文](message-context.md)与[表情](stickers.md)。
- 群消息成功持久化后才确认网关收件进度；重复平台消息只入账一次，窗口内后到的真实 @ 证据可补强记录。
  已离开处理窗口的历史消息按平台 ID 去重，不因重放重新建任务。
- 决策游标只推进连续完成区间；失败不当作静默，也不会阻止后续明确 @ 独立排队。
- 每个请求独立记录当前、提交、接受、生成和完成发送的版本。`submitted_revision` 表示交给执行层，
  不代表 `turn/start` 已确认；`accepted_revision` 当前保守地在成功 Turn 后推进，不声称模型理解了全部内容。
- 通常按请求保存独立的原生 Thread，并验证上下文检查点后选择增量输入或完整快照。
  已判定的补充可合并后通过 `turn/steer` 追加，确认 ACK 后才推进输入基线；图片／权限等改变或
  无法确认追加时走取消与恢复流程。短回复合批使用一次性 Thread，不绑定各成员的后续任务。
  应用记录仍是权威输入，旧版本即使完成，也不会发布未发出的旧稿。
- 最终文字、图片和引用按结构化结果投递；commentary、工具输出和中间 JSON 不直接转发。
  长任务由 Codex 使用 `task_update` 编写开始说明和进展；普通短回复不固定发送机械回执。
  默认最终回复最多 3 条气泡，长任务使用独立容量；表情由模型按语境调用，不设整请求仅一次的限制。
  投递逐条保存确认，并遵守 QQ 被动回复窗口。
- 在途发送无法撤回。超时、服务端错误、无法确认的 ACK 和重启时残留的 `Sending` 都视为未知，
  暂停该请求，人工核对后恢复；已确认成功的气泡不整组重发。

已支持私聊、图片／语音转写、表情、分类记忆、定时任务和独立管理界面。默认记忆在北京时间
04:00 整理，可提取静默聊天；直接改写既有正式记忆仍需明确确认，见[记忆规则](memory.md)。
按配置运行的任务与自然主动续聊是不同能力；不会仅因无人回应就自动找话题。
运行入口不负责自动部署、更新系统服务或推送 Git。

## 命令交互菜单

当 `reply_format = "markdown"` 时，命令回复使用标题、分组和加粗字段；不依赖 HTML、
表格或客户端未明确支持的代码块。`/help` 提供状态、模式、模型、技能、工具、记忆和任务入口。
`/mode` 展示后台配置的模式名称、当前模式及说明，保持原来的模式 ID 和切换语法。

- `/models` 或 `/model`：查看完整模型名和思考强度；有配置权限时选择本对话默认模型。
- `/model next`、`/model once` 或 `/models next`：仅为自己的下一次新请求选模型。
- `/models 2` 或 `/models next 2`：翻页，每页四个预设；按钮保留完整别名，显示标签至多十字符。
- 普通群成员打开模型菜单时，只提供个人下一次选择。私聊可以设置自己的默认模型，参与模式固定逐条回应。
- `/tools`：完整显示各工具状态，包括记忆、定时任务和表情包工具；管理员的启停按钮按六项分页，`/tools 2` 翻页，文字模式保留完整状态和手动命令。少量技能和扩展能力也提供相应操作按钮。更长的列表仍可按提示输入命令。
- 每个按钮都是“填入命令”，由用户检查并发送；不会自动提交，也不通过回调绕过原有权限检查。

应用将键盘限制为每行两个、最多十个按钮；翻页和返回按钮也计入上限。
按钮标签中的换行、制表等控制字符会规范化为空格，底层命令和原配置保持原样。
旧按钮即使来自管理员菜单，实际发送命令时仍按当前发件人、当前会话和最新权限判断。
按钮与待发送气泡一起持久化；恢复旧记录时没有 `command_buttons` 字段的气泡继续兼容。

`reply_format = "text"` 时保留可手动输入的文字说明，不发送键盘。QQ 明确拒绝或无法确认发送
结果时仍沿用原有交付状态，不额外尝试纯文字重发，以免产生重复消息。
真实 QQ 客户端的排版与较多行按钮效果需在部署后验收；离线测试覆盖负载、权限、分页和恢复。

协议参考：[QQ Markdown](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/type/markdown.html)、
[群消息与键盘字段](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html)。

## 构建与离线验证

已有 Rust 环境可继续使用 Cargo。此机使用独立 Conda 环境，重建描述为
[`environment.dev.yml`](../environment.dev.yml)，不向系统 Python 或 Conda base 安装项目依赖。

```bash
mamba env create -f environment.dev.yml
mamba run -n clawmingle-dev bash scripts/dev-checks.sh
```

环境已存在时直接执行第二条。脚本使用两个编译任务并关闭开发调试符号，运行 fmt、check、
全部默认测试、零警告 Clippy、二进制构建及 Git/QQ 诊断工具测试。它不启动群聊或调用模型。
生成的开发二进制是 `target/debug/clawmingle`；`--help` 和无参数运行不会启动服务。
脚本同时构建 `clawmingle-hook-proxy` 与 `clawmingle-hook-input`。复制或打包部署时，
这两个辅助程序应与 `clawmingle` 放在同一目录并设置为 `0755`；运行时自动发现，
无需配置开发机路径。原生多代理和浏览器随已授权的工作区任务启用，
[命令 Hooks](native-hooks.md) 由后台显式导入、启用，默认不执行。

另有手动、默认跳过的隔离初始化测试：

```bash
mamba run -n clawmingle-dev env CARGO_BUILD_JOBS=2 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 cargo test --test social_isolation_smoke -- --ignored
```

该测试需要本机原生 Codex 和可用的非特权 bubblewrap，仅握手并退出，不加载认证，
不创建 Thread/Turn，不访问 QQ、Jev 或模型。原有 `app_server_smoke` 会调用真实模型，继续默认跳过。

## 配置和独立认证

将 [`config/clawmingle.example.toml`](../config/clawmingle.example.toml) 保存为仓库外的
`~/.config/clawmingle/social.toml`。目录设为 `0700`，文件设为 `0600`。
QQ/Jev 密钥分别放在同目录的 `qq.env`、`jev.env`，文件设为 `0600`。
前者使用 `QQ_APP_ID`、`QQ_APP_SECRET`，后者使用 `TYPESAFE_API_KEY`；不要复制到源码或聊天中。

`allowed_groups` 使用测试群的平台 OpenID，不能填写普通 QQ 群号。首次登记时先将它设为
`[]`，再运行一次性登记工具：

登记工具需要 Python 3.11+ 和 `websockets`。在项目外创建一次性环境后运行，
不依赖开发机的 `.local` 目录：

```bash
python3 -m venv "$HOME/.cache/clawmingle-qq-register"
"$HOME/.cache/clawmingle-qq-register/bin/python" -m pip install 'websockets>=14,<16'
"$HOME/.cache/clawmingle-qq-register/bin/python" -B scripts/qq_smoke.py --register-group "$HOME/.config/clawmingle/social.toml" --seconds 600
```

在测试群真正 @ 机器人并发送工具展示的本次 `/clawmingle-register` 口令。工具仅接受
精确口令，将该群标识原子保存到仓库外的 `0700`/`0600` 配置，随即关闭连接；不发送回复，
不调用模型，不输出群标识。已有其他群白名单会拒绝覆盖。先结束登记连接，再启动群聊。
真实 @ 可由专用事件、全量群事件中的服务器自指标记 `mentions[].is_you = true`，
或与已知机器人身份匹配的结构化 mention 确认；仅在正文输入机器人名字不算。
命令与口令间允许换行或多个空格，仍拒绝多余文字、不同大小写或不同口令。
诊断只展示固定状态与布尔比较，不记录正文和平台身份值。

启动时自动创建 `data_dir/runtime/` 中的私有 `codex/`、`sqlite/`、空 `workspace/`，
并在缺失时生成最小 `codex/config.toml`（`0600`）。现有文件保留。
需要自定义 Provider 时参考 [`config/social-codex.example.toml`](../config/social-codex.example.toml)。
通用工具依赖按[自动准备流程](native-runtime.md)检查、安装和绑定。
用独立 Codex 登录或独立 API 凭据提供认证，
**不复制个人 `.codex` 的配置、auth、Skills 或历史**。没有独立认证会拒绝启动。

后台可在明确授权后只复用认证文件，不导入其他个人状态；运行入口不会自动读取个人 `.codex`。

可在空的独立目录中使用 `codex login --device-auth`，显式指定此处的独立 `CODEX_HOME`，
并清空继承的 Provider 凭据。按官方页面在浏览器完成设备代码登录；一次性登录码和原始登录输出
也只保存在仓库外私有位置，不写入普通日志或聊天。[官方认证说明](https://learn.chatgpt.com/docs/auth)

其他模型服务使用该配置中的 `model_providers` 定义，可通过社交配置的 `codex.provider`
选择。只支持 Codex 所需的 Responses 协议；不能将任意 Chat Completions 服务视为兼容。
服务商实际兼容性需单独联调。[官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)

API 凭据可放在另一个 `0600` 的环境文件，并设置 `codex.credentials_file`。
OpenAI 使用 `OPENAI_API_KEY`，其他服务使用其 Provider 声明的 `env_key`。
文件只写环境变量赋值，值可以加英文单引号；程序解析文件，不执行其中的 shell 内容。

认证与元数据使用机器人独立的 App Server；QQ/Jev 密钥不交给模型工作环境。
有 `workspace_exec` 授权的会话使用原生执行器，只有该群／私聊的 `/workspace` 可持久写入，
选定 Skills 和必要程序只读挂载，不挂载个人 Codex Home、宿主项目或其他会话。
同群任务共享该群工作区，不能将其视为成员间私有文件隔离。
浏览器、个人 Apps/MCP 和 Hooks 另按导入、启用及会话授权开放，默认不导入个人账号状态；
聊天内容、引用和模型输出不能扩大授权。共享 App Server 的网络与隔离执行器的网络边界不同，
浏览器通过受控公共网络通道访问网站。详见[原生工作环境](native-tools.md)、
[浏览器](native-browser.md)、[多代理](native-agents.md)和[Hooks](native-hooks.md)。

旧版 bubblewrap 的安全边界依赖挂载顺序：先创建全部目标路径，最后挂载私有持久目录，
之后不在可写绑定下创建节点。当前实现和回归检查遵循这一顺序，不通过本项目升级系统包。
[官方安全说明](https://github.com/containers/bubblewrap/security/advisories/GHSA-pxhw-h44j-8pfx)

## 手动联调与恢复

```bash
target/debug/clawmingle check --config "$HOME/.config/clawmingle/social.toml"
target/debug/clawmingle run --config "$HOME/.config/clawmingle/social.toml"
```

`check` 仅验证配置格式和本地配置权限；不验证真实 API 认证或平台权限。
`run` 是明确的前台启动，按 Ctrl+C 停止；它不安装常驻服务。
开始前先完成测试群登记、独立模型认证和授权域检查。

停止后可查看内部编号和版本，不显示原文、群标识或凭据：

```bash
target/debug/clawmingle status --config "$HOME/.config/clawmingle/social.toml"
target/debug/clawmingle retry 0 --config "$HOME/.config/clawmingle/social.toml"
target/debug/clawmingle resolve 0 1 0 sent --config "$HOME/.config/clawmingle/social.toml"
```

编号依次为配置中的群序号（从 0 开始）、请求号（如 R1 对应 1）、气泡序号（从 0 开始）。
`retry` 重新排队失败判断和可安全重试的失败请求，不自动重试未知发送。
`resolve` 必须基于人工核对的结果，最后一个值是 `sent` 或 `not-sent`；它只更新本地状态。
恢复旧版本未知发送时，会保留最新版本的排队或取消状态，不复活过时气泡。
所有写操作持有本机锁，不能与正在运行的 Bot 同时操作。

默认近期处理窗口为 500 条、24 小时，活跃来源和未完成判断另需保护。窗口裁剪与 SQLite
完整存档分开；Codex rollout/sqlite、任务产物、记忆和备份也不因此删除。上下文增量和
检查点规则见[消息上下文](message-context.md)，数据清除不能只靠缩小上下文窗口。
活动来源不会挡住后续已处理消息的清理；若整个窗口仍被未完成工作占满，新消息存档但不入队，
程序会提示并保留 /status、/cancel 等恢复命令的处理能力。腾出空间后需重新发送未入队的消息。

## Jev 分支判定（策略版本 5）

同一次请求并行询问独立语义问题，保留各自完整概率，程序按逻辑分支采用结果：

1. `reply_boundary`：当前说话人是否明确要求机器人不要回复。
2. `exchange`：话是对机器人、某位群友，还是开放群聊说的。
3. `you_referent`：当前说话人自己的“你/您/you”指机器人、人类、不明确或不存在；不误用引用中的代词。
4. `participation`：按当前模式是否适合参与。明确对机器人说或指代机器人时进入回应，明确禁言优先。
5. `relation`：新回应、追加、修改、取消，固定四种操作；不混入任务编号。
6. `task_target`：若操作需要已有任务，单独选择目标；无匹配则新回应澄清，不猜别的任务。
7. `audience`、`style`：回应对象与表达方式。图片是否表情继续单独判，不影响回应分支。

连续文字和表情可共同追加到同一未完成表达；已完成回答后的新解释问题通常新建回应。
“取消任务，不用回复”仍执行经过权限检查的取消，并且不新建回复。其他明确不回复的消息保持静默。
权限、版本和并发检查仍由程序负责。尚未开始的答疑优先于可选闲聊；等待超过一分钟的闲聊
恢复原序优先级，避免饥饿，不打断已经执行中的任务。新增概率不回写或重跑历史决定。
## 当前会话的机器人称呼

启用 `identity_manage` 后，已配置的本会话管理员可以直接说“以后在这里叫你爪爪”或
“恢复默认名字”。Codex 根据完整语境判断这是持续改名，还是建议、玩笑、转述或举例；
含义不明确时才澄清，明确要求不重复确认。它使用工具写入当前群／私聊的身份字段，
成功落盘后才能声称改好。工具只开放 `read`、`set_name`、`reset_name`，不允许编辑整份人格。

本会话 `display_name` 优先于共享 Identity 中的名字，下一次 Codex 回复和 Jev 的对象识别
都会读取它；提到新名字本身不等于强制 @。默认名称仍由 `persona/IDENTITY.md` 定义，
`persona/SOUL.md` 定义共享性格。各群和私聊隔离，重启／重置聊天上下文不会丢失称呼。
这不会修改 QQ 官方账号昵称或头像，也不会给其他群改名。定时任务沿用本会话名字，
但不能自行发起改名。

宿主检查当前执行轮次、原始消息来源、全部贡献者的设置管理权限、字段长度和预期版本；
拒绝旧来源覆盖新改名，保存失败不更新内存。同一来源的成功重试不重复递增版本。
名称含义与意图由 Codex 判断，来源校验不等于程序独立验证了自然语言意图。
错误改名可用明确新指令改回或恢复默认。状态记录最后修改来源和版本供排查；
不向模型开放其他会话路径或共享人格文件写权限。

## 明确请求时 @ 群成员

用户可以说“@她一下，告诉她准备出门”，Codex 根据当前对话中的身份线索选择成员。
输出 `mentions: [{participant, bubble_index, source_seq}]`，最多三名不同成员，每人一次；
`participant` 使用上下文里的稳定别名，`bubble_index` 是文字气泡从0开始的索引，
`source_seq` 指当前任务中明确要求提醒的消息。程序只解析本群已观察到的发言者或
入站原生 @ 对象，不接受昵称、QQ 号、其他群 ID 或 @全体。没有可靠身份线索时先询问，
用户也可直接 @ 那位成员以建立对应关系。

仅对话中提及某人不会自动发通知。成员改昵称后仍按 ID 对应；不会把“有人找你”
冒充提醒已送达。既有失败/结果未知的投递规则继续生效，不因 @ 功能自动重发。

群档案现支持按群保存用途、AI 角色、风格、边界，后台与群管理员的明确聊天指令共用版本化状态。参见 [后台群档案说明](admin.md#每群独立的群档案)。群内名称、全局 Identity/Soul、群档案与记忆各自保留；档案不能提升权限。


## mode-3 热聊节奏

同一会话继续只运行一个主模型任务。额外的启动间隔通过配置控制：

```toml
[traffic]
mode3_start_interval_ms = 6000
mode3_chat_interval_ms = 15000
```

间隔按上一次开始尝试计算，包含失败尝试，范围 0–60000 毫秒，闲聊间隔不能小于普通间隔。
首个请求不额外等待；这不是每条回复额外加 6/15 秒。连续实际启动至少间隔 6 秒；
非定向、可选闲聊通常至少间隔 15 秒；等待满 60 秒后恢复普通间隔和原有 FIFO 优先，
避免持续提问使它永久排队。真实 @、语义上对机器人说话和实质问题优先；等待
闲聊间隔的请求不会挡住已可启动的问题。等待期间消息继续入档、判断和按语义合并，
状态仍为排队，不伪称模型已执行。mode-1/2/all、私聊和独立定时任务不使用这一节奏。
不限制表情发送数量，表情冷却默认仍为 0。

本机制只控制本应用的主任务启动与追加，不能控制同账号其他 Codex 窗口或原生任务
内部工具后续模型调用。它降低重复输入和密集启动，不代表已确认或消除了上游 429 的
具体原因；不会自动重放失败任务，也不宣称这些间隔是模型服务的官方额度。
