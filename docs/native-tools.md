# Codex 原生工作环境

ClawMingle 优先复用 Codex 的执行、文件、Skills 和 MCP 机制。应用自己的工具负责 QQ 接口、会话授权、任务协调、记忆与素材管理、结果投递。通用任务不应新增逐网站、逐操作的 ClawMingle 工具。

## 配置与行为

接入 Codex app-server 后自动准备工具环境，没有额外的迁移开关。启动时检查原生 Codex、bubblewrap 和运行依赖，复用可用安装；缺少用户态浏览器依赖时由随程序发布的准备流程安装到应用私有目录。首次部署不依赖开发者机器路径，也不读取开发者账号。已有显式 runtime 配置优先保留。

需要支持 `environment/add`、thread/turn `environments` 的 Codex（验证基线为 0.161.0）。会话 `enabled_tools` 中的 `workspace_exec` 延续已有的执行授权，实际执行自动使用原生工具。没有此授权的会话不会因为浏览器或 Skill 授权获得任意命令执行能力。

| 能力 | 执行者 | ClawMingle 的职责 |
| --- | --- | --- |
| 命令、终端、文件编辑、查看图片 | Codex 原生工具和 `exec-server` | 创建、绑定及回收会话环境 |
| Skills 的发现和按需读取 | Codex `selectedCapabilityRoots` | 只挂载本会话选择的 Skill 包 |
| 页面导航、快照、点击、滚动、截图、页面脚本 | 官方 Playwright MCP | 绑定原生 MCP、提供受限公共网络接口 |
| 搜索 | 既有 Codex 原生 web search | 保持独立模型配置 |
| 多代理 | Codex 原生 V2 派生、协调与等待 | 继承当前任务授权，回收整棵任务进程树 |
| 命令 Hooks | Codex 原生事件与结果解释 | 后台可选导入，将命令送入当前隔离执行环境 |
| TikHub、TinyFish 等已授权服务 | 既有服务/MCP 接口 | 延续现有会话授权和凭据隔离 |
| QQ、任务控制、记忆、素材、投递 | ClawMingle 专用工具 | 环境特有的状态与平台接口 |

浏览器继续遵循 `/capability on|off browser`，全局依赖会在启动时自动准备。复用安装的 Playwright 包所带的官方 MCP，不复制桌面浏览器、不安装网站专用插件。个人邮件、网盘、Notion 等账号应用默认关闭，可在[后台能力目录](codex-capabilities-admin.md)中显式选择导入、启用及授权。

## 执行边界

共享 app-server 负责认证与元数据；有工作区执行授权的任务使用单独的 app-server worker，复用机器人独立配置与持久线程。每次执行创建单独的、无认证的 `exec-server`：只有当前会话的 `/workspace` 可持久写入，选定的 `/skills/<name>` 和必要程序只读挂载，临时目录及进程/网络空间独立。不会挂载个人 Codex Home、宿主项目或其他会话。原生执行环境不可用时本次执行失败，不回退到 app-server 的本地命令环境。多代理继承和任务退出行为见[原生多代理](native-agents.md)；Hooks 的导入与执行适配见[原生 Hooks](native-hooks.md)。

ClawMingle 以临时回环 WebSocket 和随机凭据连接 exec-server 的标准 stdio 协议。每次恢复线程重新登记环境、重建 MCP 会话，并显式在 `turn/start` 绑定环境。取消、超时和任务结束均回收执行进程及浏览器网络请求。环境注册和浏览器凭据不交给模型。

浏览器使用新的匿名上下文，通过原生 SOCKS5 TCP 通道访问公共网络；宿主检查全部 DNS 结果、固定目标地址并核对实际连接地址。HTTP/HTTPS 的 POST 等请求、WebSocket、service worker、原生下载均可使用，不再额外限制每页请求数或累计流量。保留连接并发与建立超时、私有地址和宿主地址阻断；不开放 UDP/QUIC 或自动导入个人登录状态。下载仍受工作区文件预算约束，网站自身的登录、反爬及访问要求仍然生效。具体边界见[原生浏览器](native-browser.md)。

截图保留官方 MCP 的图像内容返回。是否成功读取具体小红书帖子、视频和评论，仍须以该任务中的真实工具结果为依据；浏览器可启动不等于已完成某个网站任务。

执行进程继承单文件 128 MiB、每进程累计 CPU 300 秒和禁止 core dump 的限制。当前工作区
在开始前及每两秒检查总文件大小（512 MiB）、条目数（8192）和目录深度（64），超限会
取消本次任务并回收执行器。检查不跟随符号链接；这是有界监测，非磁盘硬配额，检查间隔内
可能短暂超过预算。整组进程的内存和数量由部署服务的 `MemoryMax`、`TasksMax` 限制。
原生工具使用 Codex 自己的调用协议和输出控制；旧 `workspace_exec` 的单次工具包装预算
不直接作用于原生命令，ClawMingle 的整任务取消与总时限继续生效。

## 验证和回退

默认测试覆盖配置、权限选择、协议字段、网络边界和生命周期。真实执行环境/浏览器检查应显式运行对应 ignored smoke，使用临时环境及合成数据；不向 QQ 发送测试消息、不复制个人认证。发布前再按仓库开发流程完成 fmt、check、test、Clippy 和敏感信息检查。

需要回退时通过既有应用发布流程恢复上一个已验证二进制。会话工具标识变化会创建新模型线程，已存 QQ 对话和 `/workspace` 文件保留；不要回退聊天数据库或删除工作区。
