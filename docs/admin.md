# 私密管理工作台

统一 Soul、分类记忆、每日整理和文件目录的新规则见 [Soul 与记忆](memory.md)。归档默认每天北京时间 04:00 进行，按用户最新决定不发送事前提醒。

ClawMingle 的 `admin/` 是本项目自带管理界面，后台为 `scripts/clawmingle_admin.py`，
部署时把同目录的 `codex_capabilities.py` 一并安装到后台脚本旁。
Python 3.11+，仅标准库，不安装系统 Python 包。管理进程与机器人分开，停止机器人后仍能重新启动。

## 功能

- 服务启动、停止、重启；进程状态、内存、自动重启次数、会话队列与失败数量。
- QQ/Jev/Responses 兼容 Provider 配置；密钥留空保留、永不回填到浏览器。
- TinyFish／TikHub 连接来源、独立 API Key 更换与清除、工具目录检查。TinyFish 可复用
  机器人 Codex 登录；TikHub 可复用现有专用配置，或在后台填写三个平台共用的独立密钥。
- 独立 Codex 登录状态；只复用认证文件、单独设备登录、退出机器人登录。不会改个人认证。
  设备登录通过 `clawmingle codex-binary --config /absolute/path/social.toml` 复用运行时的安装发现与校验，
  支持原生安装、官方 npm 安装及配置中的 `~` 路径；登录始终使用独立的临时 HOME。
- 群白名单、各群模式和模型预设、独立上下文重置；私聊开关、白名单与会话数量。
- 实际可用模型及对应思考强度目录，通过隔离 App Server 的 `model/list` 获取，不创建回复。
- Identity 身份与 Soul 人格分别编辑；实时／缓存／关闭搜索，工具清单和全局默认开关。
- 本机能力目录：选择导入 MCP、Skills 或独立机器人账号已连接的应用。个人应用默认关闭，
  导入、启用和会话授权分别管理。详见[能力目录](codex-capabilities-admin.md)。
- 文字指令型 Skill 的新增、编辑、启停、移除，目录为 `data_dir/skills/<name>/SKILL.md`。
  有执行授权时由 Codex 原生发现只读挂载的选定 Skill；其余会话沿用文字指令。
  Skill 导入不会自动执行脚本或安装依赖。

目前执行器可选择的思考强度是 `low/medium/high/xhigh`；模型目录保留服务返回的全部强度，
新增未支持的值会明确拒绝，不能静默改成其他强度。

## Identity 与 Soul

「人格与能力」分别编辑两个共享文件：`data_dir/persona/IDENTITY.md` 定义名字、身份与角色；
`data_dir/persona/SOUL.md` 定义性格、价值取向和交流习惯。界面显示实际内容与来源，所有群聊
和私聊共用；成员画像和会话记忆仍按会话隔离。参与模式只决定接话时机。

旧配置继续读取 `social.toml` 的 `soul`（留空时使用默认人格）。首次在新版后台保存身份与人格，
会写入两个文件、启用 `persona_files = true` 并移除旧的内联 `soul`。旧自定义人格中若包含名字，
请将其移入 Identity；不会擅自把自定义名字改成 Codex。文件模式下只以文件为准，不合并内联配置；
共享名字或角色冲突时 Identity 优先；已通过 `identity_manage` 保存的本会话称呼优先于共享名字。旧客户端仅提交 Soul 时更新 SOUL.md，并保留已有 Identity。

Identity 最多 2000 字，Soul 最多 8000 字，文件模式下均不能留空。它们与 Skills 共用指令容量预算，
不会扩展工具权限。目录要求 `0700`、文件要求 `0600`，不接受符号链接。文件缺失、内容无效或权限
异常会使配置检查失败，不能悄悄退回默认人格。保存沿用空闲检查、停机、操作锁、校验与失败回滚，
两个文件和配置一起提交；聊天中的管理员起名只保存本会话身份字段，无需重启，详见[会话称呼](social-pilot.md#当前会话的机器人称呼)。
外部手动编辑需自行检查配置并重启。已开始的任务不会中途替换人格。

现有备份会收录这两个文件；不自动启用备份，也不把它们挂载给模型任意改写。

## 回答方式、模式提示词和上下文

在「人格与能力 → 回答方式与参与模式」编辑以下内容：

- 总体回答策略、Markdown 排版与分段规则。
- 闲聊、直接问答、概念讲解、比较选择、问题排查、任务执行与创作、情绪回应、必要澄清八类的名称与提示。
  Codex 结合请求选择或组合，不增加 Jev 调用；显式的“简短／详细”要求优先于默认表达偏好。
- 四种模式的显示名称；mode-2、mode-3 的 Jev 参与判断提示。回答风格由统一 Soul 与任务类别规则管理，旧模式回复文案保留只读存档。
  mode-1 仅真实 @ 回应、mode-all 每条回应的程序规则固定；私聊仍为 mode-all。
  中间模式识别对机器人上一答的追问、纠正和其他成员的补充；引用机器人和时间相邻本身都不强制回复。
- Jev 人类消息窗口（1–40）、机器人回复气泡窗口（1–20）；Codex 人类消息窗口（1–80）、
  机器人回复气泡窗口（1–40）。默认分别为 20、6、20、20。
- 一次回复总气泡／图片数量（1–3）和单文本气泡字符数（1–2000）。这是应用的容量上限，
  不要求模型把回答写满；不是 QQ 全平台极限。超过发送容量的大型成果需要另行以支持的产物形式交付。

Jev 的人类窗口取当前消息之前的记录，当前消息另附；Codex 取最近人类记录，当前请求关联消息另附，
可能与窗口重合。命令消息不占这些窗口。引用和活跃请求状态另附。机器人摘要带实际发送时间、
请求所有者、回复对象和来源消息，并按发送时间排序。Jev 的 24 KB 和 Codex 的 128 KiB 消息输入预算
会在需要时裁减旧上下文；因此配置值是条数上限，并非每次保证携带这么多条。
当前请求必需内容本身超预算时明确失败，不静默丢弃。

窗口不决定历史保存期限。完整历史继续按会话归档，Codex 可以使用历史工具按 ID、时间和关键词检索。
已有 `context_messages` 配置兼容保留，独立窗口未设置时继承它。
「填入默认规则」只更新表单，点击保存才生效。名称变更同步至模式选择、`/mode`、`/status` 和 `/help`，
命令使用的固定编号不变。编辑无权覆盖工作区隔离、工具授权或模型输出结构。

运维可运行 `clawmingle behavior --config /absolute/private/path/social.toml` 查看有效设置和默认规则；
输出仅含上述非凭据配置。管理员自行写入提示词的私人内容仍应按本地配置保护。
回归中的真实 Jev 测试默认忽略，仅在明确设置 `CLAWMINGLE_JEV_EVAL_CONFIG` 后手动运行；使用合成对话，
不连接 QQ、不修改真实聊天记录。判断准确率仍需持续观察，提示词不是确定性保证。

## 权限与事务

管理服务仅绑定 `127.0.0.1`，默认端口 `17430`。所有 HTML、资源、健康检查及 API 都必须
携带受限代理令牌 `X-CM-Dashboard-Proxy`；令牌来自仓库外 `0600` 文件，不进入前端。
personal-dashboard 在 `/apps/clawmingle/` 逐请求验证管理员会话，对写入再验证 Origin、CSRF
和 JSON 类型。匿名、过期会话及未经授权的直链均被拒绝；浏览器 Cookie、认证头不透传后端。

网页只提供固定机器人服务操作和固定配置字段，不接受任意系统命令、文件路径或服务名称。
配置、登录和会话修改先检查空闲状态，短暂停止机器人并取得 operator 锁，原子保存后检查
配置，失败恢复旧文件，最后恢复原来的运行状态。忙时返回 409，前端保留尚未保存的编辑。
退出机器人登录后保持机器人停止；新认证完成后可重新启动。

重置上下文保留历史快照，后续请求不再引用旧上下文。有发送结果未知的消息时拒绝重置。
管理界面的重置不是长期记忆删除，也不删除会话工作区文件。

## 群记忆与临时群文档

每个群和每个私聊分别维护本地正式记忆、结构化草稿与修订历史。后台的记忆页可切换会话，查看分类、来源原文引用、确定性、有效期、归档状态及目录用途。草稿正文可以编辑或撤回；对正式记录提出更正会先生成草稿，管理员明确确认后才直接改写，版本冲突不会覆盖新内容。

默认每天北京时间 04:00 由机器人读取本会话聊天历史并筛选、分类、追加归档，包括此前无需回复的消息。后台可调整频率、时刻、短期有效期和自动提取开关。程序保留观察/推断的区别，不从玩笑固化人物关系。原有 `clawmingle-memory.timer` 继续处理旧版已确认资料与到期草稿，不另起模型提取任务。

`store.json` 是唯一事务真值，`authority/` 和 `documents/memory/` 提供分类与草稿视图；直接改镜像不会导入。任务工作区通过独立工具接入，认证目录和其他会话不挂载给 Codex。全部运行资料留在 Git 外。详细布局、权限、容量与回滚规则见 [记忆说明](memory.md)。

## 通用工作区工具

### 任务与扩展、表情包

“任务与扩展”可调整复杂任务时限、工具预算、单命令时限、最终气泡容量和进展消息频率。
开始说明和进展单独记录；等待用户补充、待取回结果在会话卡片中分别显示。详见
[长任务说明](long-tasks.md)。这些设置不改变模式的参与职责，也不要求每条回复变长。

公共网页浏览与文档插件在各会话的“本会话扩展授权”中单独开启。页面只展示已登记的
能力名称及查询工具数，不展示端点凭据或宿主路径；全局工具开关不能代替会话授权。
详见[扩展授权说明](scoped-integrations.md)。

“表情包”管理静态／动态素材、标签、适用与避免场景、启用状态及自动使用冷却。
编辑与删除检查素材版本，旧页面不能覆盖新修改。动态预览展示采样帧；聊天发送使用
原图，已生成的待投递副本不因删除素材而丢失。素材在私有数据目录中，不能进入 Git。
详见[表情包说明](stickers.md)。

`workspace_exec` 授权自动接入 Codex 原生命令、编辑与图片工具；每个群及每个私聊都有独立的
持久工作区，位于 `data_dir/workspaces/g_<哈希>` 或 `p_<哈希>`。执行进程只看到自己的
`/workspace`、只读系统工具和临时目录，不挂载机器人认证、配置、记忆真值或其他工作区。
它不直接联网；公开信息通过内置搜索及单独网页工具读取。Python、Shell、Git 可用，Node、rg
取决于本机已验证的工具；浏览器自动准备时也会提供 Node。
详见[原生工作环境](native-tools.md)及[自动准备流程](native-runtime.md)。

`/tools` 查看当前工具，群命令管理员用 `/tool on|off 名称` 为本会话切换，
`/tool default` 恢复全局默认。后台开关设置全局默认；会话覆盖独立保留。
命令限时、限输出并受资源约束，取消会终止进程，不自动重试可能已修改文件的命令。

`time_now` 提供当前时间；`public_web_read` 读取公开 HTTPS 文本，不执行网页脚本或登录；
`weather_current` 提供带地点、数据时间的天气模型估算，不能称为现场观测。

## 群内安装 Skill

已配置的群命令管理员可发送 `/skill-install GitHub链接`，也可以明确对机器人说
“Codex，请安装这个 Skill：链接”。程序验证真实发送者身份和明确安装意图；
普通讨论、历史描述或引用内容不会触发安装。只下载完整的文字指令文件，不执行来源安装脚本。
成功后在当前对话启用；`/skill on|off 名称` 控制会话启用，后台开关控制全局启用。

## 引用消息上下文

群聊和私聊都将新发言与被引用内容分开传递给 Jev、Codex。引用包含原作者、文字、
QQ 语音转写及其可用状态、附件类型、图片数量和有界嵌套内容；卡片只保留描述摘要。
引用机器人不会自动视为 @，仍按当前参与模式和 Jev 判断；引用中的命令、ASR 不授予权限。

平台只给引用索引时，程序在当前对话的入站索引或已确认发送 ACK 中精确查找，补齐原文、
作者、时间和媒体。找不到、索引冲突或原消息尚未确认送达时，不猜测原内容。
解析最多 24 个节点、四层及 12000 字符文字；模型投影另有总预算，省略内容明确标记。

引用图片按具体来源读取：机器人图片使用对应 ACK 的不可变快照；用户图片优先读取精确
匹配且未过期的本会话缓存，再尝试平台提供的图片地址。缓存来源、内容校验和过期时间
保存在工作区外，不能将旧引用直接对应到最新的 `input:1` 或 `sent:1`。
本轮视觉输入仍最多三张；缺失、过期或超过限额的引用图片明确标为不可用或省略，保留
可用文字上下文。缓存不是永久图片档案；新批次会替换旧批次，已过期原图可能需要重发。

## 安装与验证

分别使用 `config/clawmingle.service.example`、`config/clawmingle-admin.service.example` 作为
用户服务模板。先在专用 venv 内运行管理后端测试，再将入口及 `qq_smoke.py`、`admin/` 复制到
受保护的应用安装目录。后台没有外部依赖，Python 环境可用 `python3 -m venv` 重建。

代理令牌在私有配置位置生成，目录 `0700`、文件 `0600`。dashboard 服务账号只取得自己
可读的独立副本，不放宽用户主目录权限。网站侧配置与鉴权测试见 personal-dashboard 的
`docs/CLAWMINGLE.md`。不需要新增公网端口或改变 Nginx/VPN/SSH。

验证入口：

```bash
python3 -B scripts/test_clawmingle_admin.py
python3 -B scripts/test_qq_panels.py
mamba run -n clawmingle-dev bash scripts/dev-checks.sh
```

上线后必须分别验证管理员页面/API、匿名直链/资产/API拒绝、过期会话、CSRF拒绝，
以及机器人停止时工作台仍可访问。不要把模拟浏览器检查写成真实上线验收。

人格与能力页还可分别开关“按消息 ID 查询”和“历史分页与搜索”。这些工具只读当前对话；
长期存档不随短期上下文清理，覆盖范围、容量和当前状态的含义见[消息存档说明](message-context.md)。

“群在线文档”页提供腾讯文档独立授权、专用目录选择/创建、群绑定与暂停。群模型获得
绑定目录的增删改查能力；不继承管理员其他文档权限。配置、版本检查、未知操作恢复和
QQ 普通文件发送的边界见[群文档说明](group-documents.md)。


表情库新增共享系列、分类概述、待描述状态和批量导入。自动收集与自动选用分别开关。
会话偏好面板展示 A（14天）、B（最近100次）、最后使用与连续分数，可立即设为偏爱、
禁用或恢复自动；作用范围仅为选中的群聊/私聊。素材编辑影响共享库，偏好不跨会话。
语义分类、概率抽选和明确规则的边界见[表情库说明](stickers.md)。

表情页面还可编辑表情包与 emoji 的自然表达策略、载入默认文字或留空恢复默认；风格包含“调侃”，情绪包含“尴尬”。表达策略不改变参与模式、工具权限或发送限额。


### QQ 原生群文档登记

「群文档」新增实际群号绑定与独立 QQ 扫码登录。先选择已登记且绑定腾讯文档目录的群，
填写群号并扫码，确认后即可让新建文档进入 QQ 的「群在线文档」列表。
可重新登录、暂停全部群登记或解除所选群登记；已有文档不受这些设置变更影响。
九类文档已验证，PDF 暂不登记。详细行为、凭据边界和结果未知时的处理见
[群文档说明](group-documents.md#qq-客户端群在线文档栏目)。

### 每群独立的群档案

“群聊管理 → 本群档案”保存四项 Markdown 文字：群用途与背景、AI 在群里的角色、互动风格、相处边界。每项最多 600 字，合计 2000 字。不同群独立保存；未配置时沿用全局 Identity/Soul，对应的本群角色、风格和边界优先于全局默认。称呼仍由本会话身份管理，工具权限和参与模式另行设置，群档案不授予权限。

新设置会用于后续回复、Jev 接话判断及本群定时 Agent 的提示词；过期版本的 Jev 判断重新排队。已生成的待投递内容不重写。正在续接的请求会刷新档案；清空档案明确撤销旧设定。后台保存沿用空闲检查和事务，失败保留原记录；并发修改产生版本冲突，编辑草稿保留，可“重新读取”后再改。重置聊天上下文保留档案；“清空档案”才恢复全局默认，且保留递增版本。备份包含档案。

启用 `group_profile_manage` 后，配置的群管理员也可在群里明确提出长期修改，例如“以后这个群按工作群来，回答直接一些”。模型先读取档案，再依据当前原始消息执行部分字段更新。普通成员、私聊、定时任务不能修改；混合了非管理员内容的请求也不允许写入。建议、引用、玩笑和临时角色扮演不应被当成永久修改，工具失败不能声称已保存。宿主验证权限、当前消息证据、版本和大小，具体自然语言意图仍由模型解释。

档案描述整个群的长期相处方式，不替代有来源的个人记忆或具体任务。现有“群偏好”记忆可以记录具体约定，但相关性召回并不保证每条都随每轮输入；不要把记忆列表中的一条记录宣称为已强制执行的规则，也不要把自动归档宣称为全员同意。
