# Codex 与 QQ 能力扩展

这份文档对应 2026-10-23 确认的后续工作。实施范围是已绑定群／私聊的独立工作区；个人 Codex 工作区、认证、其他会话和宿主服务不随能力扩展开放。

## 原生能力与应用能力

- **Web search**：主聊天进程通过 Codex 原生托管搜索工作，当前运行配置选择 `web_search = "live"`。`public_web_read`、`weather_current`、`time_now` 是 ClawMingle 补充工具。搜索有结果不等于目标网页完整可读，估算天气也不等于气象站实测。
- **语音**：当前默认 `gpt-6.1-sol` 的官方模型说明与本机 bundled metadata 均为文字／图片输入，不支持音频输入。继续用 QQ 参考转写交给 Jev 与 Codex；缺转写时明确说明未听懂。标准 turn 协议容器存在 audio 字段，以及实验 Realtime 接口，都不能证明当前模型支持原音频。本轮不增加语音输出。
- **原生 steer**：对已经被应用关联为同一请求的追加／修改，使用原始连接、线程与 `expectedTurnId` 向正在运行的 turn 递交。旁观聊天与独立请求不会因为时间接近自动合并。原生调用不会新建 turn，也不改变该 turn 的模型、权限和工具。
- **原生 memory**：当前版本有原生记忆能力，但共享 bot CODEX_HOME 下的记忆不是独立群记忆。ClawMingle 继续以本地正式群记忆和聊天存档为真值，不能直接打开全局 memory 开关而造成群／私聊混用。原生记忆兼容需要另做隔离视图与明确的同步规则。

来源：[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Web search](https://learn.chatgpt.com/docs/web-search)、[当前模型输入能力](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[原生记忆](https://learn.chatgpt.com/docs/customization/memories)。

## 补充消息的确认与竞态

本地排队、RPC 接收确认、模型消费输入、最终生成和 QQ 投递是不同事实：

1. 本地递交记录推进 submitted revision。
2. `turn/steer` 确认正确 turn 后，推进 Codex 接收记录。
3. 使用 `clientUserMessageId` 关联原生 `UserMessage.clientId` 的输入事件，随后才能接受新 final answer。
4. 同回合的后一个完整结构化答案取代旧草稿，不能将两个 JSON 拼接。
5. ACK 成功但没有对应输入后的最终答案时，保留最新请求并开启后续 turn，不把旧答案记为新要求已回答。
6. 已结束、拒绝、连接失败或确认不明时不盲重发 steer；中断并确认旧回合结束，再处理保留的新版本。未确认中断会退出该后端运行路径，禁止复用未知状态。
7. 新图片需要重新建立绑定；模型／Skill／工具策略变更也走新 turn。原生生图阶段已经离开主文字 turn 时，不再强行 steer。

接收确认与最终回答仍不等于 QQ 已收到；沿用原有 Sent／Failed／Unknown 投递状态。[原生客户端关联字段的版本化测试](https://github.com/openai/codex/blob/rust-v0.161.0/codex-rs/app-server/tests/suite/v2/turn_steer.rs)验证的是 `clientId`，不是服务端 item ID。

## 本轮实现与验收边界

- **消息按钮**：用户已实际确认帮助按钮出现，点击后填入命令，发送后成功收到回复。这证明命令按钮链路；不据此宣称所有卡片、回调按钮或各客户端类型都已验收。
- **Skills**：管理员可以在聊天里明确要求安装公开 GitHub Skill；下载固定版本完整包，在本对话隔离工作区只读挂载，支持调用包内脚本／资源。管理页展示来源、版本、文件数与启用范围。详情见[技能包与资料查询](skill-packages.md)。
- **QQ 资料**：真实只读探测成功读取机器人昵称／头像 URL、测试群名称／人数／介绍、机器人群内状态。成员列表和详情返回权限错误；没有已验证的公开头像／昵称／简介修改接口。本机开放工具不能代替 QQ 授权，也不能用 soul 设置冒充 QQ 资料修改。
- **通用调度与主动推送**：支持一次性／周期固定提醒、到点运行 Codex 的任务、暂停／恢复／取消／立即运行、查询执行结果和处理发送失败。仅在当前对话执行和投递，任务首版输出文字；模型任务可使用该对话的历史检索、联网与已启用 Skill 工具。主动推送默认关闭，管理员明确要求提醒或推送时可由工具开启。用户已于 2026-10-23 实测私聊自然语言创建提醒并成功收件；服务端确认 Sent、QQ ACK 和历史归档。测试群的平台状态允许主动消息，但群主动收件仍未单独验收。见[调度说明](social-tasks.md)。
- **长期历史与备份**：已有按 ID／时间／关键词检索原文及当前处理状态；新增一致性快照、校验、分页离线读取和导出恢复副本。自动每日备份已实现，默认关闭，没有新增系统定时器。正式记忆继续以本地记录为真值。见[备份说明](backups.md)。
- **原生多代理**：工作区任务使用 Codex V2 子代理，复用原生执行工具、MCP 及完整历史派生的 Skills／动态工具；每个任务独立回收进程，具体继承限制见[原生多代理](native-agents.md)。
- **原生 Hooks**：后台可选导入、启停本机 command Hooks，默认不导入；原生引擎处理事件、匹配和结果，命令在本任务工作区执行。见[原生 Hooks](native-hooks.md)。

多人共同提出的请求不能继承首位提问者的管理员权限。调度工具在每次调用时读取已经持久化的来源消息，只有所有贡献者均有本对话管理权限时才允许变更；混合权限请求可以查看任务，管理操作请由管理员单独发出 `/task` 命令。

验证覆盖模拟 App Server 的 steer 接收／拒绝／结束竞态、任务执行／投递／重启恢复、跨会话和管理员边界、技能包完整性／工作区挂载、QQ 查询错误和备份恢复。真实模型音频能力、平台权限与 QQ 客户端收件分别记录，不能以离线测试替代。

## 后续集中讨论的事项

先完成明确的接线与测试，再讨论以下设计，不抢先启用：

- **应用事件 Hooks**：已接入的 Codex 原生 Hooks 不覆盖 Jev 判断、QQ 发送等应用事件；若用户需要“发消息前检查”等体验，还需定义应用层事件、可执行动作、超时、权限和失败处理。
- **任务档案推断**：候选档案可包含目标、参与者、时间约束、待办、已确认决定和证据消息 ID。建议先生成可修订的候选档案，区分用户陈述、模型推断与用户确认，修订保留来源／版本；不要把性格、职业等推测直接写入正式人物真值。
- **原生记忆兼容**：优先讨论按群／私聊导出给原生记忆的最小视图、哪些记忆可回流、删除／撤回语义以及后台提炼用量。保留本地权威层，避免两个系统互相覆盖。
- **小游戏**：先确定接龙／占卜等玩法、参与与退出、每群独立状态、过期、主持权限和消息频率；占卜应作为娱乐内容，不当作人物事实进入长期记忆。

Hook 参考：[官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)。
